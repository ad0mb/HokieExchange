# HokieExchange frontend conventions

This is a hackathon repo (VTHACKS) with a Next.js 16 App Router + TypeScript + Tailwind v4 frontend in `frontend/`, backed by a FastAPI + MySQL/Databricks backend in `backend/`. Multiple teammates touch this code under time pressure, so consistency matters more than cleverness — match what's already here rather than introducing a new pattern.

## Adding shadcn components

Install components with the CLI from inside `frontend/`:

```bash
npx shadcn@latest add <component>
```

This project was initialized on the **base-ui** flavor of shadcn, not Radix (`components.json` has no `"style"` tied to Radix primitives — check `src/components/ui/sheet.tsx` if unsure, it imports from `@base-ui/react`). This matters for one specific pattern:

- **Use the `render` prop, not `asChild`, to compose a custom trigger element.** Radix-based shadcn docs/examples online use `asChild`; that prop does not exist on this project's primitives and will fail to type-check. Instead:

  ```tsx
  <SheetTrigger render={<Button variant="ghost" size="icon" />}>
    <Menu className="h-5 w-5" />
  </SheetTrigger>
  ```

  See `src/components/ui/sheet.tsx` for more examples of this pattern (e.g. the built-in close button).

Never hand-edit generated files under `src/components/ui/` to fix a styling need — that's the primitive layer and should stay close to what the CLI generates. Build one-off styling on top of it in `src/components/marketplace/` instead (see below).

## Brand color tokens

Virginia Tech colors are defined once, in `src/app/globals.css`, and must be used through those tokens rather than hardcoded hex anywhere else in the app:

- `--brand-maroon` (`#861F41`) — primary brand color, buttons, active/selected states, borders on brand elements
- `--brand-maroon-dark` (`#6b1934`) — hover/pressed state for maroon elements
- `--brand-orange` (`#E5751F`) — accent color: prices, the "Exchange" wordmark, category icons, links like "Book here"

These are wired into Tailwind via the `@theme inline` block, so use them as ordinary utility classes: `text-brand-maroon`, `bg-brand-maroon`, `border-brand-maroon`, `hover:bg-brand-maroon-dark`, `text-brand-orange`, etc. If a design calls for a shade of maroon/orange that doesn't exist yet, add a new CSS variable next to the existing ones in `globals.css` rather than writing a raw hex value inline.

Everything else (grays, backgrounds, `--muted`, `--border`, ...) uses the default shadcn neutral palette — leave those alone.

## Icons: no emoji

Use `lucide-react` icons for all iconography (nav items, category markers, service placeholders, buttons). Do not use emoji characters in the UI — the goal is a clean, professional look, not something that reads as thrown together. `lucide-react` is already a dependency; import icons by name, e.g. `import { Scissors, Sparkles } from "lucide-react"`.

## File layout

- `src/components/ui/` — shadcn primitives only, as generated by the CLI. Don't add app-specific components here.
- `src/components/marketplace/` — HokieExchange-specific UI built from those primitives (navbar, sidebar, service-card, logo, location-badge, etc). New feature-specific components go here, named after what they render, one component per file.
- `src/lib/` — data and utilities. `categories.ts` and `services.ts` hold mock data shaped like the real MySQL/Databricks schema (id, category slug/label, price, seller, description, ...) so that swapping in real API calls later is a drop-in replacement of the data source, not a rewrite of the components that consume it. Keep new mock data in this same shape.
- `src/app/` — routes (App Router). Each route's page composes components from `src/components/marketplace/`; avoid putting marketplace layout logic directly in a `page.tsx` beyond assembling components and passing data.

## Quick sanity check before committing UI work

1. Would this run through `npx tsc --noEmit` and `npx eslint src` clean? (No `asChild` on base-ui components, no stray `any`.)
2. Are all colors either a brand token above or a default shadcn/neutral token — no raw hex?
3. Are icons from `lucide-react`, not emoji?
4. Is the new file in the right place per the layout above?
